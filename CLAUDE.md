# Octapu System: notes for Claude

A markdown-based project management system (PMS). It holds several **entities** (separate organisations, each a folder listed in `_Dashboard/entities.csv`), each made of **tentacles** (its orgs and sub-orgs, rows of `_Options/Tentacles.csv`). A project's person in charge is its **leader** (`_Options/Leaders.csv`). Data are plain markdown and CSV files that the user also edits by hand (e.g. in Obsidian) and shares between machines with Syncthing. `_Dashboard/` is a local web app that reads and edits those files.

The README is the user-facing reference. Its sections on file layout, code organisation, options and markdown formats are accurate, so read the relevant section before changing behaviour. `_Help_Guide.md` is the step-by-step guide shown in the app.

## Running
- `node _Dashboard/server.js` → http://127.0.0.1:4173 (`PMS_PORT`, `PMS_HOST` env vars). No `npm install`; there is no package.json.
- There's no test suite. Verify by running the server and exercising the page or API (curl the `/api/*` routes; POSTs need `Content-Type: application/json` and a matching `Origin`).
- The repo *is* the user's live data. Test against a copy (e.g. `tar` the folder, minus `.git`, into the scratchpad and run there on another `PMS_PORT`), so edits, change logs and conflict files don't land in real files. Pick the entity for a curl with `-b "pms_entity=Label"`.
- Developed on Windows (Git Bash + PowerShell). Python isn't assumed; use node for scripts.

## Hard rules / conventions
- **Zero dependencies.** Node built-ins only on the server, plain browser JS (IIFE per file, `'use strict'`) on the client. No build step, no frameworks, no CDN.
- **Data folders vs app**: each entity's folder (`Label/`, `Freelance/`, from `_Dashboard/entities.csv`) holds `_Tentacles/`, `Projects/` (and any other dir named in its `PROJECTS`, relative to the entity folder), `_Networking/`, `_Time_Management/`, `_Catalogs/`, `_Options/`, `_Incubator.md`, `_Archive.md`. `_Images/` and `_Help_Guide.md` stay shared in the main folder. All of these are user data. `_Dashboard/` is the app (its `entities.csv` is the user's too). `_Dashboard/defaults/` holds the shipped Help Guide, screenshots, logo and colours, which are copied in only if missing.
- **Help Guide is duplicated**: `_Help_Guide.md` (root, the user's copy, which has a "Mark as read" tick) and `_Dashboard/defaults/_Help_Guide.md`. Doc changes go in both. Update README too. Screenshots live in `_Dashboard/defaults/Screenshots/` and `_Images/Screenshots/` (same names). They were last made (2026-11) by driving headless Chrome over the DevTools protocol from a throwaway node script against a seeded scratch copy, with `os.hostname` overridden so no real computer name shows. `HelpGuide.pdf` in the root is printed from the rendered help page the same way (Chrome `Page.printToPDF`: logo/title header, faint logo watermark, no sidebars or Mark as read, a small two-column contents that fits page 1, and each `##` step starting a new page). Regenerate it whenever the guide or its screenshots change. The guide's headings have no step numbers: the help page builds a numbered contents list from its `##` headings (`addContents` in `js/help.js`), and cross-references are `[Heading](#slug)` links (slug as `markdown.js` `slug()`). `md-link` only opens a new tab for links that don't start with `#`.
- Comments are short, plain English, explaining *why*. Match the existing style; the user cares about tidy, readable code.
- User-visible text uses British spelling (colour, organise).

## Server (`_Dashboard/server.js`, ~2.4k lines, one file plus helpers)
- Helper modules: `todos.js` (status-prefixed items, header parsing), `document-edits.js` (block/milestone/line edits), `catalogs.js`, `changes.js` (line diff, change logs, Syncthing conflict names).
- Routing is a flat `if (url.pathname === …)` list in `http.createServer`. All POSTs go through `handleEdit(req, res, isValid, apply)`, which checks `isTrustedRequest` (same origin, loopback by default), requires JSON, validates the body with an `isX` predicate, then runs `apply` inside `enqueueWrite` (writes are serialised).
- `apply` returns `{ code, body }`.
- **Writing files**: `writeFileSafely(full, data)` (temp file + rename) for existing files. New files use `fs.promises.writeFile(..., { flag: 'wx' })`. Markdown writes are logged to the changelog (see below), so new markdown write paths must go through `writeFileSafely` or call `recordCreated`.
- **Path safety**: documents are addressed by `{ folder, file }`, never raw paths. `editableFile(folder, file)` resolves them: a project folder name, `tentacle:<ID>`, `networking:<page>`, or `archive` (`_Archive.md`, for the Archive Index's Raw view and double-click edits; field values use the `value` kind of `api/text`). It only matches real listed entries.
- `listMarkdown(dir)` lists the `.md` files of a project or tentacle folder, skipping Syncthing conflict copies.
- **Main file**: `primaryFile(project)` / `pickPrimary` picks the file named after the folder's title (`namedFile`, case and `_`/space insensitive), else the first alphabetically. `project.files` and a tentacle's `files` are sent main-first, which is the file tab order. Compatibility flags a project with no named file (`missingMainFile`, `choose: 'main'`). Its Fix issues takes `main` (renamed to `Title.md` with its change logs by `renameToMain`) and `leader` (a leader tag for missing, empty or unknown Leader problems marked `choose: 'leader'`). A header still saying `**Owner**` (the old name, read by `findLeader` in todos.js) is the fixable "Owner should be Leader" (`fix: { renameLeader }`, `renameOldLeader`); `_Archive.md` entries with it are extra Projects rows keyed `archive:LINE` (`oldLeaderEntries`, `fixArchiveLeader`).
- **Options** (the entity's `_Options/Options.csv`, `Option,Value`): read fresh on every use via `readOptions()`. On/off options are declared in `SWITCH_OPTIONS` with defaults. The Options page lists them as tick boxes even when absent from the file, and saving adds them. Add a `TOGGLE_NOTES` entry in `public/js/options.js` for each new switch. Dropdown options go in `CHOICE_OPTIONS` (values + fallback, read with `readChoice`) with a `CHOICE_NOTES` entry; ARCHIVEMODE is the only one.
- **Archived projects**: `isArchived(p)` = dated folder (`ARCHIVED_FOLDER`) or any Date Closed (`project.closed`, set in `listDirectory`). Use it, never the folder regex alone. Archived projects are hidden everywhere, even with SHOWARCHIVED. The project page's Archive button (`archiveProject`) sets Date Closed, then by ARCHIVEMODE either appends the header to `_Archive.md` (HEADERS, default; folder untouched because it's moved off to a NAS) or renames the folder `YYYY-MM-DD_…` (FULL). The Timeline's `archive` rows come from `_Archive.md` (HEADERS) or archived folders (FULL), never both. Archived projects only appear (Timeline rows, the Archived filter or Archive Index) while SHOWARCHIVED is on. FULL: the projects list's Archived filter. HEADERS: no filter; the menu's Archive Index (`archive.html`, `/api/archive`, add `/api/archive-entry`, remove `/api/archive-remove` via `removeNamedEntry`). In HEADERS, archive entry titles (`TENTACLEID Title`, same shape as `projectName`) are dependency targets: `resolveDependency(value, projects, archive)` gives `archive:Title`, `dependencyChoices(..., archive)` lists them as "(archived)"; pass `dependableArchive()`. `_Archive.md` holds 8 "Demo" entries (Nov 2024 to Nov 2026) added on purpose to show the Timeline zoom. Commitments were removed (2026-11) and `Commitments.md` is no longer read.
- **Incubator page** is a document like the Archive Index: `folder: 'incubator'` (`INCUBATOR_FOLDER` in `editableFile`), Ideas/Raw/Changelog views, conflicts, and double-click edits (`block` on the heading, `value` on the dependency via `raw.line`, `body` on the notes via the `parseBlocks` body).
- **Folder button** (`folder-button` template in the summary card's `corner`, `documentView.folderButton`, one document click handler): `POST /api/open-folder` → `openFolder` resolves only listed projects (`listProjects`) or `tentacle:ID` (`tentaclePlace`), then `spawn(FILE_BROWSER, [dir], { detached })` (`explorer.exe` / `open` / `xdg-open`), not awaited, with an `error` handler.
- **Tentacle Timeline**: `/api/timeline?tentacle=ID` (`tentacleTimeline`: rows whose `projectTentacleId` is ID, or archive entries starting with it; no events or releases). tentacle.html keeps `#timeline` (with `data-tentacle`) in a hidden `#timeline-holder`; `tentacle.js` `draw()` moves it into the Overview's `[data-timeline-slot]` (`tentacle-timeline` template) and back before each redraw, then fires `resize`. timeline.js drops the line tick boxes and legend items when `data-tentacle` is set.
- **Contacts** (renamed from Leads, 2026-11): `NETWORKING.contacts`, page `contacts`; its `file` is a getter (`contactsFile`) that gives `Leads.md` while that exists without `Contacts.md`. `?page=leads` and `[[Leads#...]]` (markdown.js `LINKABLE_FILES`) still open Contacts. Compatibility's **Core files** page (`type=core`, `CORE_RENAMES`, `incompatibleCoreFiles`, `fixCoreFile`, `renameWithLogs` shared with `renameToMain`) renames it, its logs and its `#` title. It also renames `_Entities` to `_Tentacles` and `_Labels` to `_Options` (`folder: true` rules): `dataPaths` picks each with `tentaclesFolder(root)` / `optionsFolder(root)`, which give the old name while it exists without the new one, and all four names are in `RESERVED_DIRS`. The settings folder's path is `OPTIONS_DIR` (was `LABELS_DIR`).
- **Task Management tab** (Options, `data-tab="statuses"`): the `statuses` table in `label-tables.js` has `groups` (one `label-panel` per status type, titled Awaiting Assignment / Assignees / Waiting for review / Complete / Archived) and `groupBy: 'type'`; rows keep their file-wide index, each plus button carries `data-group`, and `askForRow(group)` sends that type. There's no Type column.
- **Task Archive** (`TASK_ARCHIVE_FILE`, `_Task_Archive.md` in the entity root): `submitWeeklyReview` first runs `takeArchivedRows` (document-edits.js, using `rowExtent`) on each reviewable file, then archives DONE rows in what's left (networking files re-find their entries with `sourceIn`). `taskArchiveGroups` groups by tentacle (projects by `projectTentacleName`) and `addTaskArchive` writes a newest-first `## Date archived:` section. The archive is written before the task files, inside the review's rollback. Each milestone tasks leave gets `<!-- N tasks in the Task Archive -->` (`ARCHIVE_MARKER`, `addArchiveMarker`, one per milestone, counts added together), which markdown.js `parseMilestones` counts as N done tasks; `renderLines` skips any line that is only an HTML comment. Only `GET /api/task-archive` reads it (the Options page's read-only Task Archive tab).
- **Entities tab** (Options): `label-tables.js` `entities` table → `GET/POST /api/entity-table` (`readEntityTable`, `saveEntityRow`, `editEntityCsv` in todos.js; rows keyed by Directory, the last can't be deleted). Adding a missing folder makes it and returns `created`, and the table's `afterAdd` selects the entity and opens `setup.html`; every change reloads the page. Removing leaves the folder.
- **Fix all issues** (compatibility.js `fixAll`): every box's `bodyOf` in turn, sorted by line descending so events and `archive:LINE` entries are fixed bottom-up.
- **Recurring tasks** (priority R): `PRIORITY_TOKEN` in todos.js also reads `[#R|nU]` (n 1–10, U in DWMY), giving `priority: 'R'`, `recur: { count, unit }` and `priorityLength` (tokens aren't 4 characters any more). `setPriority` takes `R|5D`; `isPriorityEdit` accepts `RECUR_VALUE`. `changePriority` schedules one period from today only when R is newly set. `POST /api/recur` → `advanceRecurring` (document-edits.js) moves SCHEDULED on with `addPeriod` (month-end clamped). Client: `data-recur` on controls; status.js sends `api/recur` instead of `change()` for a recurring status name or tick box, and choosing R opens `recurForm` (`recur-fields` template). sidebar.js `recurState` (overdue / due within `RECUR_SOON_DAYS`) puts them first with `recur-*` borders. markdown.js strips the R token too.
- **Todos from Contacts/Events**: `collectTodos` adds `networkingFiles()` items inside an entry, with `networking: { page, name, title }` (no tentacle); `status.itemLink` links them to `networking.html?page=X#Title`, and sidebar.js `projectOf` skips them.
- **`##`-entry files** (`_Archive.md`, `_Incubator.md`, in the entity's folder): `parseNamedEntries(markdown, FIELDS)`, `addNamedEntry`, `addEntryMark` in document-edits.js, and `appendNamedEntry` in server.js. Incubator ideas are `## TENTACLEID Title`, and are hidden once they have `**Archived**:` or `**Promoted**:`. Promote uses `makeProject` (shared with New project).
- **Events** (`NETWORKING.events`): fields with a `kind` (`date`, `range`, `yesno`) have their own controls and are written on one line by `setInlineField` via `POST /api/event-field`. Dates are stored `YYYY-MM-DD` or `YYYY-MM-DD to YYYY-MM-DD` (`parseEventDate`). Hand-written dates are read by `readOldEventDate` and converted on Compatibility > Events (`incompatibleEvents`/`fixEvent`, keyed by heading line + title). Events list as Upcoming/Past by date, ignoring the file's headings. `eventProgress(entry)` gives open/applied/booked (from the Yes/No fields): it drives the card borders and the Events page filters (`?filter=`, since `#` is used for entry links), and on the Timeline only open events get a deadline line and only booked ones are purple (others grey).
- **Task and milestone menus** (added 2026-11): Cancel/Delete moved out of the status menu (which now lists statuses with type icons/colours, no type headings) into a grey row menu (`status.rowMenu(item, where)`, via `renderOptions(doc, lines, where)` → markdown.js `ctx.rowMenu`, and the sidebar's `todo-item`). Milestone tasks also get Move to (`/api/row-move`, `moveRow`) and Promote to new milestone (`/api/row-promote`, `promoteRow`); project/tentacle tasks get Create linked Scratchpad block (`/api/row-block`, `linkRowToBlock`). Milestone cards' grey menu (`milestone-menu-actions`, handled by project.js through `status.onMilestoneAction`): `/api/milestone-promote` (`makeProject` with header and `### Milestone 1` body, then `removeMilestone`), `/api/milestone-done` (`finishMilestone`), `/api/milestone-remove`.
- **Review flag**: `**Flagged for Review**: Yes` under Date Reviewed (`setReviewFlag` in todos.js, `parseHeader().flagged`), toggled by `POST /api/review-flag` from the Reviewed box (`status.reviewedValue`), coloured like the Review box it puts the page in (`review-flag-projects` cyan, `review-flag-tentacles` purple). `collectToReview` includes flagged files and `markReviewed` removes the flag. The Review page's yellow first box is WAITING type tasks (`waitingTasks()`, from `collectTodos`, drawn with `todo-item` and status controls), counted by the menu's yellow `nav-count-waiting` (`roundup.waitingTasks`, hidden at 0). The menu's green `nav-count-done` is `roundup.doneToReview` (`doneSinceReview`, the Review page's Done since the last review).
- **Review agenda** (added 2026-11): `_Time_Management/AgendaItems.csv` (`Type,Item,Checked`), the Options page's Agenda tab (`label-tables.js` `agenda`: rows addressed by index + `fromItem` as items can repeat; `toRow`/`toBody` split a rule into Type REVIEW/REVIEW_ALL and its target, and the Item column's `options(row)` comes from `readAgendaTable().choices`; Checked isn't shown). `parseAgenda`/`parseAgendaRule`/`editAgendaCsv` in todos.js, `collectAgenda` (cards on `/api/weekly-review` as `agenda`), `POST /api/agenda-table` and `/api/agenda-check`. `submitWeeklyReview` unticks every row last. Rule items look like wiki links, so never pass them through `md.inline`. `AGENDA_GROUPS` names can't be PROJECTS directories (`projectDirError`). `REVIEW|Dashboard` (`AGENDA_PAGE`) and the Incubator, Catalogs, Deadlines and Bookings groups give `links` cards rather than `entries`. The top-level group is `TopTentacles`; the old `Entities` keyword maps to it (`OLD_AGENDA_GROUPS`).
- Other label CSVs: `Status.csv`, `Tentacles.csv` (tentacles, `id,Name,Parent`; renamed from `Owners.csv` on start-up by `renameOldTentaclesFile`), `Leaders.csv` (people, `Tag,Name`), `Colours.csv` (theme).
- `/api/tags.js` is a script every page loads that sets `window.PMS_*` globals (`PMS_TENTACLE_IDS`, `PMS_PROJECTS` (dependencyKey of each live project's name → folder, for `[[TENTACLEID Title#Heading]]` links in `markdown.js` `wikiLink`, checked before tentacle IDs), `PMS_ENTITIES` and `PMS_ENTITY` (the dropdown), archived statuses, SHOWARCHIVED, MULTIUSER, SYNCCONFLICTS, ARCHIVEMODE, the logged-in user). Use it for small per-page flags.
- `serveStatic` redirects every `.html` to `setup.html` while first-time setup is needed. When MULTIUSER is on, it redirects to `login.html` if no one is logged in.

## Client (`_Dashboard/public/`)
- Every page loads `api/components.js`, `js/projects.js` (shared helpers on `window.PMS`: `component`, `getJson`, `postJson`, `readJson`, `escapeHtml`, `setViewInAddress`, …), `api/tags.js`, then page scripts.
- **HTML only in templates**: `public/components/*.html` `<template name="…">`. Use `{{x}}` for escaped values, `{{{x}}}` for raw HTML and `{{#if x}}…{{else}}…{{/if}}` for optional markup. Newlines and indentation are stripped. Render with `PMS.component(name, data)`.
- Document pages (`project.html`, `tentacle.html`, `networking.html`) share `js/document-view.js`. Each has a `[data-view]` toggle (Overview/List, Scratchpad, Raw, Changelog) and a `draw()` that renders the current view into `#content`. The loaded doc object carries `folder` and `file`.
- `js/changes.js` (`PMS.changes`) provides the Syncthing conflict warning (`#conflicts` above `#content`) and the Changelog view for those pages.
- `js/timeline.js`: `/api/timeline` also sends `releases` (catalog rows with a Release date, `timelineReleases`), drawn as white `gantt-release` lines with a hover card. KINDS tick boxes cover rows (active/inactive/archive) and lines (deadlines/bookings/releases), all in `pms.timeline.hidden`. Zoom (3/6/12 months, `pms.timeline.zoom`) sets `--gantt-month` from the scroller width; `showNearbyRows` hides rows with no bar within 2 months of the months on screen, on scroll, and arrows only join visible rows.
- `js/nav.js` is the left menu, which shows the logged-in user and Log out when MULTIUSER is on. `/api/nav` sends every tentacle (`tentacleTree`: `parent`, `root`, `level`); nav.js nests them as `nav-branch` details, closed until opened (`pms.nav.open`, the reverse of the groups' `pms.nav`), coloured with the `org-level-*` classes.
- **Sidebars** (`js/layout.js`, loaded after projects.js on every `.shell` page): widths as `--nav-width`/`--todo-width` on `.shell` (the grid uses clamped `--nav-col`/`--todo-col`), collapse as `.nav-collapsed`/`.todos-collapsed` (a 36px rail), saved in `pms.layout`. Its `sidebar-toggle` and `sidebar-resizer` elements sit beside each sidebar in `.shell` (fixed on wide screens, a bar when stacked at ≤1100px), because nav.js and sidebar.js redraw the sidebars' innerHTML. Changes fire a window `resize` for the Timeline. Menu labels are `.nav-label` spans, one line with an ellipsis.
- **Todos sort** (`sidebar.js` `SORTS`): project (default, `itemLink` label A–Z), status, type, priority, scheduled, deadline; `OLD_SORTS` maps earlier saved values.
- **View bar**: pages with a `.toggle` keep it, plus a project's back link, Project type and Archive, in a sticky `.view-bar` above the `.topbar` title (`html:has(.view-bar)` sets `scroll-padding-top` so scroll targets clear it).
- **Tentacle tabs** (`tentacle.js` `drawTabs`): one `org-tab-row` per level along the open path (`openPath`), ancestors `is-on-path`; the plus ends the last row and its dialog's **Under** picks the parent. `js/status.js` holds the status controls plus `status.refresh()` / `status.onChange()` for reloading after edits.
- Styling: `public/css/style.css`, using CSS variables (`--green`, `--pink`, `--orange`, `--yellow`, `--accent`, `--surface`, `--border`, `--text-soft`, …). A global `[hidden] { display: none !important }` means the hidden attribute always wins over a rule that sets display. Every plus button (`.add-button`, and `.timeframe-add`/`.entry-date-button` without `.is-set`) shares one rule: `img/circle-plus-outline.svg` (a hollow circle) as a mask, 16px, coloured `--surface-raised`, accent on hover. On `project.html` (`body.project-page`) the plus buttons and `.facts` boxes are cyan instead, matching the project review flag. Minus buttons (`.row-remove`) match: `img/circle-minus-outline.svg`, 16px, the same colours, pink on hover. A section heading's plus (`.section-row .add-button`) and Active Timeframe's come before the text (`order: -1`).
- Generate report (`js/dashboard.js`) clones the Overview; it fires `pms:report-start`/`pms:report-end` so the Timeline shows every row (and redraws arrows) for the copy.

## Entities, tentacles and leaders (added 2026-11)
- `readEntities()` reads `_Dashboard/entities.csv` (`Name,Directory`) on every request; no usable rows means one entity at the main folder (`FALLBACK_ENTITY`). The `pms_entity` cookie picks one (`selectedEntity`, set by `POST /api/entity-select`, which also runs `prepareEntity`).
- `http.createServer` runs `route()` inside `requestContext.run({ root, entity })`; `handleEdit` adds `user` to that store. **Every data path is `at().X`** (`dataPaths(currentRoot())`: `TENTACLE_DIR` (the `_Tentacles` folder), `OPTIONS_DIR` (the `_Options` folder), `TENTACLES_FILE`, `OPTIONS_FILE`, `ARCHIVE_FILE`, …), never a module constant, so new code must use `at()` too. `ROOT_DIR`, `HELP_FILE`, `IMAGES_DIR` stay constant. Start-up runs `prepareEntity` for each entity.
- The entity dropdown is `PMS.entityPicker()` in `js/projects.js` (menu, setup and login pages). Per-entity browser storage (Plan picks, sidebar filters, milestone collapse) is keyed by `PMS_ENTITY`.
- Naming: in code and UI, a row of Tentacles.csv is a **tentacle** (`readTentacles`, `tentaclePlace`, `TENTACLE_PREFIX`, `tentacle.html`, `/api/tentacle`, `/api/tentacle-tag` for a page title's tentacle keyword) and the person is a **leader** (`**Leader**` header, `LEADER_FIELD`). "Entity" only means an entities.csv folder. `entity.html` redirects to `tentacle.html` and `compatibility.html?type=entities` maps to `tentacles`. The header/leader/type buttons share the `header-control`/`header-button` classes.
- `collectNav` sends `compatibility` counts (rows on each Compatibility page), shown orange (`nav-count-issues`) in the menu.

## Multi-user and Syncthing (added 2026-11)
- NAS read/write modes were considered and **rejected**: Syncthing handles sharing files between machines. Don't reintroduce network-path options.
- `SYNCCONFLICTS` switch: scans the open document's folder for `Name.sync-conflict-YYYYMMDD-HHMMSS-DEVICE.md`. It shows a diff with **Keep current** (deletes the copy) or **Use this version** (writes it over the file, then deletes the copy). API: `GET /api/conflicts`, `POST /api/conflict`.
- `MULTIUSER` switch: login picks a leader from `Leaders.csv`, stored in the `pms_user` cookie. The device is always the server's `os.hostname()`, never user-chosen, so the number of logs stays stable. Every markdown write appends to `<name>-change.<HOSTNAME>.log` next to the file. There is **one log per device** so Syncthing never sees two writers on one log. Entries older than 2 × `ROUNDUP` days are pruned on write. The Changelog view merges every device's log for the file (`GET /api/changelog`).
- User identity reaches the write helpers through `AsyncLocalStorage` (`requestContext`), set in `handleEdit`.
- Trust model: collaborative equals, so no passwords or encryption. The login is identification, not security.
